# 全宋词「整本回放」排查（2026-10-18）

> 现象：`python export_precise.py --prefer-largest-screen` 抓
> `2c4320a0813ab9dc1g01317b 全宋词`（佚名）时，12260 章都已落盘，脚本却从目录
> 第 10039 项起一路「已导出章重复出现…跳过落盘、不占章号」空翻，看起来永远结束不了。
> 结论：章文件名按**字典序**排序，`9999.md` 被当成最后一章 → 续传锚点回退到书中部。
> 修复见 commit `8c46c61`。

## 一、现场

| 证据 | 内容 |
|---|---|
| 中间产物 | `output/2c4320a0813ab9dc1g01317b/chapters` 12260 个 md（`raw` 同数），`_catalog.json` 12298 项 |
| 日志 | 连续 `↩ 已导出章重复出现「…」…跳过落盘、不占章号`，标题却在推进（满庭霜·述怀 → 满庭霜·和前 → … → 兰陵王·和吴宣卿）——阅读器在**按目录顺序回放已导出章** |
| 关键读数（修复前） | `get_last_chapter_title()` → `(踏莎行·秋思, 9999)`；`is_export_complete_after()` → False；`missing_catalog_positions()` → **9033** |

也就是说：产物其实已经抓到第 12260 章，脚本却以为「最后一章」是第 9999 章
（目录第 10038 项），于是从第 10039 项接着抓 —— 那一整段早已导出。

## 二、根因：章号只补零到 4 位，字典序把 5 位名排到最前

章文件名是 `f"{idx:04d}.md"`，超过 9999 章的书会出现 5 位名。字典序里
`"10000.md" < "1001.md" < "9999.md"`，于是「最后一个文件」= `9999.md`。

| 位置 | 修复前的错误后果 |
|---|---|
| `get_last_chapter_title()` | 末章认成 `9999.md`（踏莎行·秋思）→ 续传锚点回退到书中部 |
| `match_disk_chapters_to_catalog()` | 贪心游标被 5 位章名带跑，后面 9003 个章文件全部对不上目录 |
| `missing_catalog_positions()` | 由 42 章误报成 9033 章缺失（补漏阶段会对着 9003 个「缺口」跳目录） |
| `disk_chapter_titles()` / `exported_chapter_texts()` | 章序错乱（后者按标题聚合，影响小） |
| 跨会话指纹（末 12 章） | 取到的不是真正最后 12 章 |
| `book_json.load_chapters_from_export_dir()` | 成品 JSON 章序错乱：`10000.md` 排到 `1001.md` 前面 |
| `detect_merged_chapters.analyze_chapter_mds()` | 体检时章序与「最大章」编号错位 |

连锁反应就是用户看到的现象：锚点 = 踏莎行·秋思（目录 10038）→ 续传跳到第 10039 项
→ 从那里线性翻页，每一章都被 `repeat_exported_chapter_evidence()` 判成「已导出章重复」
跳过（不落盘、不占章号），既不会有新增、也到不了书末，只能把两千多章空翻一遍。

## 三、修复（commit `8c46c61`）

1. **章文件一律按章号数值排序**：新增 `chapter_file_number()` / `list_chapter_files()`，
   `export_precise` 里所有读章文件的地方（末章标题、磁盘标题、正文摘要、目录对齐、
   跨会话指纹、成品 md/JSON 顺序）统一走它；`book_json.load_chapters_from_export_dir()`
   与 `detect_merged_chapters` 的章文件排序同步改为数值键。
2. **整段回放兜底**：连续跳过 `REPLAY_EXPORTED_SKIP_LIMIT`(12) 章已导出内容
   （落盘新章即清零）即判定阅读器在回放，每会话最多一次目录重定位回续传点；
   定位不推进就结束会话、按已有产物收尾，缺口交给补漏阶段 —— 不再线性空翻。

## 四、验证

在同一份产物上复算（只读）：

| 读数 | 修复前 | 修复后 |
|---|---|---|
| `get_last_chapter_title()` | `(踏莎行·秋思, 9999)` | `(曹休齐, 12260)` |
| 续传目标 `next_catalog_title()` | 满庭霜·述怀一带 | 末章「贺新郎·海棠次刘草窗韵」 |
| `missing_catalog_positions()` | 9033 章 | 42 章 |
| `stale_chapter_artifacts_evidence()` | None | None（产物可信，可续传） |

单测：`python -m pytest tests -q` **401 项全绿**（新增 9 项：5 位章号的排序、末章识别、
目录对齐不串位、成品 JSON 章序、体检章序、回放计数）。

重跑该书即可收尾：脚本会跳到末章「贺新郎·海棠次刘草窗韵」抓完并按书末结束。

## 五、遗留：42 项「词牌·副题」被并进邻章

修复后仍缺的 42 项不是丢内容，而是**切章没切开**，正文落在邻章文件里：

| 目录项 | 实际落在 |
|---|---|
| 定风波令·再次韵送子瞻·般涉调 | `0241.md`（标题「定风波令」，同文件里连着两首） |
| 卖花声·题岳阳楼 | `0449.md`（标题「卖花声」） |
| 水调歌头·黄州快哉亭赠张偓佺 | `0454.md`（标题「水调歌头」） |

即目录写「词牌·副题」，正文页顶栏/切章只认「词牌」，于是副题那一首被并进同名词牌章。
与明词三百首的「尾括号」是同一类问题（那次修的是「（首句）」，这次是「·副题」）。

注意：补漏阶段（`fill_missing_chapters`，单次上限 12 章）会按目录去跳这 42 个标题，
跳过去可能把邻章正文重复落盘。建议先跑 `python detect_merged_chapters.py` 复检这本书，
再决定是否收紧切章规则（按目录尾副题切分）后重抓，而不是直接依赖补漏。
