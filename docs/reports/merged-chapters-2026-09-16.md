# 明词三百首「反复重抓」排查（2026-09-16）

> 现象：`a31325d0813ab8198g01754d 明词三百首`（张璋 刘卓英）每轮批量都被重新抓取，
> 中间产物从 9-11 起反复被写、产品 JSON 一直生不出来。
> 结论：切章规则认不出「正文只印主名、目录带尾括号」的写法，逻辑章卡死 →
> 导出跑不出 JSON → 下一轮又被当成新书。修复见 commit `cb2aac6`。

## 一、现场

| 证据 | 内容 |
|---|---|
| 成品 | `~/data/weixin/books/` 下**没有**该书的 JSON |
| 中间产物 | `output/<id>/chapters` 只有 8 个文件，`0003`–`0008` 全是**同名**「谢应芳（五首）」 |
| 时间戳 | `raw/0003`–`0008` 分别是 9-11 20:41、21:50，9-12 08:09、09:40、10:35、11:27 —— 每跑一次多一个重复章 |
| 清单 | 同时在 `data/new_books.txt`（第 3 行）与 `data/dup_books.txt` |

每轮流程：清单里没成品 → 当成新书开抓 → 卡死在中途 → 不写 JSON → 下一轮重复。

## 二、根因：目录带尾括号，正文页只印主名

该书目录 476 项里 **473 项带尾括号**，两类写法都有：

```text
谢应芳（五首）                      ← 作者分组行：主名 + 首数
忆王孙（齐云一炬起红烟）             ← 词牌 + 首句
清平乐（二首）（山翁归去）           ← 连续两个括号：首数 + 首句
```

而阅读器正文页只印主名，后面跟副题与正文：

```text
谢应芳
谢应芳(1296—1392)，字子兰，号巢老人。武进（今属江苏）……
忆王孙            ← 目录写「忆王孙（齐云一炬起红烟）」
和熊元修苏州感兴
齐云一炬起红烟，顷刻烟销事已迁。折戟沉沙月烂船。
【说明】……
```

`find_chapter_split()` 只找「目录里的下一章」且要求**整行等于目录标题**，
「忆王孙」永远匹配不上「忆王孙（齐云一炬起红烟）」→ 逻辑章停在「谢应芳（五首）」
不动，一路翻到书末（跑到 1312 行/54 页仍在涨）。越章救援同样只认整行等于目录标题
（`exact=True`），也认不出「杨基」=「杨基（七首）」，所以跳页漏章后也接不住。

阅读器实测（临时 Playwright 探针逐屏 dump `__wr_chars`）：

```text
顶栏「谢应芳（五首）」   页内：谢应芳 / 小传 / 忆王孙 / 和熊元修苏州感兴 / 齐云一炬起红烟…
find_chapter_split(页, 目录, "谢应芳（五首）") = None      ← 修复前
```

## 三、修复

- `split_catalog_title_tail()`：把目录标题的**尾部括号逐个剥离**（支持连续两个），
  返回 (主名, [括号内容…])；
- `title_base_matches_line()`：整行等于主名时才算章首，且括号内容要成立——
  - 首数（「五首」「二首」）：直接放行（正文里不会出现）；
  - 首句：必须能在紧随其后的几行里找到，用来区分同名小令（本书《念奴娇》有 12 处）；
  - 短括号（「（上）」这类 ≥2 字以下）：不做正文佐证，一律不认，避免被常用字误命中；
- **正常切章与越章救援两条路径都启用**：阅读器跳页漏章时（本例跳过「陶安（二首）」
  与两首《水调歌头》），越章靠主名匹配接住，缺章交给补漏。

  `detect_merged_chapters.py` 不再命中该书。
