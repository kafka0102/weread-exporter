# 组诗同名章「整段回放」排查（2026-10-20）

> 现象：抓 `09032110813ab9f4cg012d20 李纾诗全集` 时，脚本反复
> 「已导出章重复出现「…」（正文与已导出章一致），跳过落盘、不占章号」，
> 目录跳转「让皇帝庙乐章」连续三次没落地，最后
> `❌ 导出失败: 连续重开阅读器仍无法前进（7 次）`、`本次: +0 章, +0 字`。
> 结论：续传/收尾进度按「同名第一项」定位，而这本书目录里**真有同名章**——
> 两组乐章都有「迎神/迎俎/亚献终献/送神」——末章「送神」被认成目录第 10 项，
> 续传目标于是退回**已导出**的「让皇帝庙乐章」。修复见 commit `92e9b1f`。

## 一、现场

| 证据 | 内容 |
|---|---|
| 中间产物 | `output/09032110813ab9f4cg012d20/chapters` 14 个 md（`raw` 同数），`_catalog.json` 13 项 |
| 日志 | 「顶栏「送神」/逻辑「让皇帝庙乐章」」→ 连串 `↩ 已导出章重复出现…跳过落盘` → 「停滞前进：翻页无新内容，「送神」→「让皇帝庙乐章」」→ 目录跳转 3 次不落地 → 重开 7 次后 RuntimeError |
| 产物章序 | 0001 版权信息 … 0009 送神（唐德明兴圣庙乐章组）→ 0010 让皇帝庙乐章（正文含「迎神」）→ 0011 奠币（正文含「迎俎」）→ 0012 酌献 → 0013 亚献终献 → 0014 送神 |

### 真实目录 vs `_catalog.json`

用本地只读探针 `.scratch/diag_catalog_dup_probe.py`（不入库：开目录面板抓 DOM、
逐项打印，并对比 `_catalog.json`）复采同一本书：

| | 目录项 |
|---|---|
| 阅读器真实目录（17 项） | 扉页 / 版权信息 / 唐德明兴圣庙乐章 / 迎神 / 登歌奠币 / 迎俎 / 德明酌献 / 兴圣酌献 / 亚献终献 / 送神 / 让皇帝庙乐章 / **迎神** / 奠币 / **迎俎** / 酌献 / **亚献终献** / **送神** |
| `_catalog.json`（13 项） | … / 送神 / 让皇帝庙乐章 / 奠币 / 酌献 —— 第二组里与第一组**同名**的 4 项不见了 |

`scrape_catalog_titles()` + `clean_catalog_titles()` 按**标题**全局去重（原本是为收敛
目录面板重复渲染），顺手把真实存在的重名章也吞掉了。DOM 实测面板里 `.readerCatalog_list_item`
只有 17 个节点，重复是**脚本多次 harvest 累积**出来的，不是 DOM 真有副本。

## 二、根因：进度用「同名第一项」定位

`catalog_index()` 只返回第一个同名项，于是：

| 读数（修复前，对现有产物复算） | 值 | 后果 |
|---|---|---|
| `get_last_chapter_title()` | `(送神, 14)` | 已导出末章 |
| `catalog_index(cat, "送神")` | 9（第一组的「送神」） | 进度被读回第一组 |
| `next_catalog_title(cat, "送神")` | `让皇帝庙乐章` | **续传目标退回已导出章** |
| `is_export_complete_after("送神", cat)` | `False` | 判不出「已经抓完」 |
| `match_disk_chapters_to_catalog()` | `0013/0014 → None` | 对齐其实早已看出「章文件跑过了目录末尾」 |

即：**保序贪心对齐本来就能正确处理同名章**（`match_disk_chapters_to_catalog` 的
docstring 就写着「目录里的同名章（组诗）也能一一对上」），但续传/收尾决策没用它，
用的是标题查找。会话于是反复跳回已导出章 → 空翻 → 目录跳转不落地 → 重开 7 次 → 抛错。

## 三、修复（commit `92e9b1f`）

新增四个按目录对齐定位的 helper（`export_precise.py`）：

| helper | 作用 |
|---|---|
| `disk_catalog_progress(md_dir, catalog)` | 已落盘章推进到的 `(目录序号, 章名)`；章文件跑过目录末尾时停在最后一条对齐项 |
| `disk_next_catalog_target(md_dir, catalog)` | 磁盘进度之后的下一章；已到末尾返回 `None` |
| `is_disk_export_complete(md_dir, catalog)` | 与 `is_export_complete_after` 同义，但按对齐位置判 |
| `disk_resume_target(md_dir, catalog, fallback)` | 续传目标；对齐不出进度时退回同名查找 |

接入点：

1. **续传锚点**（`run_session` 会话开始）：锚点、完成判定、下一章目标全部按对齐进度取；
2. **回放纠偏**：连续跳过已导出章后重定位的目标同样按对齐进度取；
3. **停滞前进**：改为「先落盘本章 → 再按磁盘进度之后的目录项前进」，对齐已到末尾就收尾，
   不再按同名查找回跳（`resolve_stale_advance_target` 只作为对齐失效时的兜底）；
4. **外层收尾**：`export_one_book` 的会话前检查与「重开前再核一次」都改按对齐进度判完成，
   顺带在没开过阅读器的收尾路径用 `load_shelf_meta` 补书名，避免把 book_id 当书名写进 JSON。

## 五、遗留

1. **目录同名去重仍会丢重名项**：本书 `_catalog.json` 仍是 13 项（真实 17 项）。
   本书内容没丢（「迎神/迎俎」正文已并进邻章 0010/0011），但目录不全仍会影响
   `missing_catalog_positions()` / 补漏阶段的精度。要修得连**按序号的目录跳转**
   （点第 N 个同名项）和「标题已作为独立行出现在邻章正文里就别再补」一起做，
   否则补漏会把邻章正文重复落盘（同类风险见 `wide-book-chapter-order-2026-10-18.md` 第五节）。
2. **抓取质量另有小瑕疵**：`0001.md` 里版权信息块重复了 4 次，`0014.md` 末尾多出
   「寞无闻。」残行，属页面重绘/翻页重叠的采集问题，与本次续传逻辑无关。
