# 组诗同名章「整段回放」排查（2026-10-20）

> 现象：抓 `09032110813ab9f4cg012d20 李纾诗全集` 时，脚本反复
> 「已导出章重复出现「…」（正文与已导出章一致），跳过落盘、不占章号」，
> 目录跳转「让皇帝庙乐章」连续三次没落地，最后
> `❌ 导出失败: 连续重开阅读器仍无法前进（7 次）`、`本次: +0 章, +0 字`。
> 结论：续传/收尾进度按「同名第一项」定位，而这本书目录里**真有同名章**——
> 两组乐章都有「迎神/迎俎/亚献终献/送神」——末章「送神」被认成目录第 10 项，
> 续传目标于是退回**已导出**的「让皇帝庙乐章」。第一轮修复见 commit `92e9b1f`
> （续传/收尾进度改按目录对齐定位），第二轮见第五节（目录不再按标题去重、按序号跳转、
> 并章项不再重复落盘）。

## 一、现场

| 证据 | 内容 |
|---|---|
| 中间产物 | `output/09032110813ab9f4cg012d20/chapters` 14 个 md（`raw` 同数），`_catalog.json` 13 项 |
| 日志 | 「顶栏「送神」/逻辑「让皇帝庙乐章」」→ 连串 `↩ 已导出章重复出现…跳过落盘` → 「停滞前进：翻页无新内容，「送神」→「让皇帝庙乐章」」→ 目录跳转 3 次不落地 → 重开 7 次后 RuntimeError |
| 产物章序 | 0001 版权信息 … 0009 送神（唐德明兴圣庙乐章组）→ 0010 让皇帝庙乐章（正文含「迎神」）→ 0011 奠币（正文含「迎俎」）→ 0012 酌献 → 0013 亚献终献 → 0014 送神 |

### 真实目录 vs `_catalog.json`

用本地只读探针 `.scratch/diag_catalog_dup_probe.py`（不入库：开目录面板抓 DOM、
逐项打印，并对比 `_catalog.json`）复采同一本书：

| | 目录项 |
|---|---|
| 阅读器真实目录（17 项） | 扉页 / 版权信息 / 唐德明兴圣庙乐章 / 迎神 / 登歌奠币 / 迎俎 / 德明酌献 / 兴圣酌献 / 亚献终献 / 送神 / 让皇帝庙乐章 / **迎神** / 奠币 / **迎俎** / 酌献 / **亚献终献** / **送神** |
| `_catalog.json`（13 项） | … / 送神 / 让皇帝庙乐章 / 奠币 / 酌献 —— 第二组里与第一组**同名**的 4 项不见了 |

`scrape_catalog_titles()` + `clean_catalog_titles()` 按**标题**全局去重（原本是为收敛
目录面板重复渲染），顺手把真实存在的重名章也吞掉了。DOM 实测面板里 `.readerCatalog_list_item`
只有 17 个节点，重复是**脚本多次 harvest 累积**出来的，不是 DOM 真有副本。

## 二、根因：进度用「同名第一项」定位

`catalog_index()` 只返回第一个同名项，于是：

| 读数（修复前，对现有产物复算） | 值 | 后果 |
|---|---|---|
| `get_last_chapter_title()` | `(送神, 14)` | 已导出末章 |
| `catalog_index(cat, "送神")` | 9（第一组的「送神」） | 进度被读回第一组 |
| `next_catalog_title(cat, "送神")` | `让皇帝庙乐章` | **续传目标退回已导出章** |
| `is_export_complete_after("送神", cat)` | `False` | 判不出「已经抓完」 |
| `match_disk_chapters_to_catalog()` | `0013/0014 → None` | 对齐其实早已看出「章文件跑过了目录末尾」 |

即：**保序贪心对齐本来就能正确处理同名章**（`match_disk_chapters_to_catalog` 的
docstring 就写着「目录里的同名章（组诗）也能一一对上」），但续传/收尾决策没用它，
用的是标题查找。会话于是反复跳回已导出章 → 空翻 → 目录跳转不落地 → 重开 7 次 → 抛错。

## 三、修复（commit `92e9b1f`）

新增四个按目录对齐定位的 helper（`export_precise.py`）：

| helper | 作用 |
|---|---|
| `disk_catalog_progress(md_dir, catalog)` | 已落盘章推进到的 `(目录序号, 章名)`；章文件跑过目录末尾时停在最后一条对齐项 |
| `disk_next_catalog_target(md_dir, catalog)` | 磁盘进度之后的下一章；已到末尾返回 `None` |
| `is_disk_export_complete(md_dir, catalog)` | 与 `is_export_complete_after` 同义，但按对齐位置判 |
| `disk_resume_target(md_dir, catalog, fallback)` | 续传目标；对齐不出进度时退回同名查找 |

接入点：

1. **续传锚点**（`run_session` 会话开始）：锚点、完成判定、下一章目标全部按对齐进度取；
2. **回放纠偏**：连续跳过已导出章后重定位的目标同样按对齐进度取；
3. **停滞前进**：改为「先落盘本章 → 再按磁盘进度之后的目录项前进」，对齐已到末尾就收尾，
   不再按同名查找回跳（`resolve_stale_advance_target` 只作为对齐失效时的兜底）；
4. **外层收尾**：`export_one_book` 的会话前检查与「重开前再核一次」都改按对齐进度判完成，
   顺带在没开过阅读器的收尾路径用 `load_shelf_meta` 补书名，避免把 book_id 当书名写进 JSON。

## 五、第二轮：目录不再按标题去重（同名章保全，commit `7fb751c`）

### 现场

用只读探针（`.scratch/diag_catalog_dup_probe.py`、`diag_catalog_dup_stats.py`、
`diag_catalog_virtual_probe.py`，均不入库）实测：

| 读数 | 值 |
|---|---|
| 本书真实目录（DOM `.readerCatalog_list_item`） | 17 项，含同名章：迎神 ×2、迎俎 ×2、亚献终献 ×2、送神 ×2 |
| 全宋词真实目录 | **17305 项**，其中 **5007 项与前面某章同名**（「浣溪沙」178 次、「菩萨蛮」143 次），另有 55 对**相邻同名** |
| 目录面板渲染方式 | **全量渲染**：17305 个节点一次全在 DOM，行高固定（≈54px），条目在滚动内容里的偏移稳定 |

`clean_catalog_titles` 按标题全局去重（原本是为收敛重复 harvest），把这些真章一起吞掉：
全宋词 `_catalog.json` 12298 项（少 5007），本书 13 项（少 4）。

### 修复

1. **按条目位置去重**：`scrape_catalog_titles` 改为 `CATALOG_HARVEST_JS` +
   `merge_catalog_harvest` 收集「滚动内容偏移 → 章名」——重复 harvest 合并，
   同名章各占一个位置；`clean_catalog_titles` 不再按标题去重。
2. **两份视图隔离**：会话里大量**按标题**的旧启发式（`next_catalog_title`、
   `is_last_catalog_chapter`、`find_future_catalog_hit`…）都假定章名唯一，喂进同名项
   会互相打转（实测重导时「正文越章：逻辑「迎神」→「迎神」」空转）。所以 `run_session` 里：
   - `catalog_positions`：完整目录（含同名章）→ 进度 / 下一章 / 按序号跳转等**位置类**判断；
   - `catalog_titles = dedupe_catalog_titles(catalog_positions)`：旧启发式继续用去重视图（行为不变）。
3. **按序号跳转**：`goto_catalog_chapter(..., cat_idx=...)` 直接点第 N 项，不再按标题命中
   第一个同名项；滚动断言两遍（面板刚打开会自己平滑滚到当前章）、坐标连续两次一致才点；
   同名章**不再**退回按标题兜底；并章/同名页的落地校验用**阅读进度区间**
   （`catalog_index_progress_window`）兜底。
4. **并章项不再重复落盘**：`split_fill_candidates` 把「同名章已在磁盘」的目录项当并章项，
   只报告不补抓；真缺口补抓前用 `blocks_already_covered` 比对全书正文行，已覆盖就跳过；
   会话落盘也加了同样的窄保险（仅限同名章）。
5. **首页不再混进上一页正文**：`goto_first_chapter` 之后清抓取缓冲 + 重绘。原来会把
   阅读器「上次读到的位置」的正文并进首页（实测首页出现版权信息块 ×4，甚至混进中段某章正文，
   成品里凭空多出一章重复内容）。

### 验证

从头重导本书（`--force`，旧产物先备份到 `.scratch/bak_lihsu/`）：

| 读数 | 修复前（旧产物） | 修复后 |
|---|---|---|
| 目录项 | 13（同名项被吞） | 17（含 4 个同名项） |
| 章数 / 章序 | 14 章；0001 混进版权信息块 ×4 | 14 章；章序与真实目录一致（版权信息 → … → 让皇帝庙乐章 → 奠币 → 酌献 → 亚献终献 → 送神） |
| 停滞前进 | 「送神」→「让皇帝庙乐章」回跳、空翻、重开 7 次后失败 | 「翻页停滞且无下一章「送神」，按全书末尾收尾」，一次收尾 |
| 补漏报告 | 无（同名项不可见） | 「2 个目录项的同名章已在磁盘（迎神、迎俎），正文多半已并进邻章，只报告不补抓」 |

单测 `python -m pytest tests -q` **418 项全绿**（本轮新增：位置去重合并、同名计数、
进度区间、旧视图去重、并章项分类、正文覆盖判定）。

## 六、遗留

1. **采集层面的重复**：首页版权信息块仍会出现两次（画布 hook 累积 + 重绘各渲染一次），
   个别末章末尾有「寞无闻。」残行。属页面重绘/翻页重叠的采集问题，与续传逻辑无关。
2. **旧启发式仍按标题**：会话内的下一章 / 末章 / 越章判定用去重视图，所以「同名章被并进
   邻章」在会话里仍表现为并章（正文落进邻章文件），只是现在会被补漏阶段**明确报出来**，
   不再静默。要根治得把这些启发式也改成位置驱动。
3. **旧目录不会自动刷新**：`_catalog.json` 只在全新导出（会话 1）时重抓，续传沿用旧文件。
   修复前抓过目录的书要重跑（或删 `output/<id>` 重导）才会拿到完整目录。
