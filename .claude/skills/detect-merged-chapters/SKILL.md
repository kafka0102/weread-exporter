# Skill: 已下载电子书章节合并体检

判断一本书的正文是否被堆进单一章节（导出时印刷目录页被当成章首，会把目录一路推到末章，
前几十章只剩标题占位），输出可人工复核的分级清单。

**优先直接跑脚本**，不要临时手写统计：

```bash
python detect_merged_chapters.py
python detect_merged_chapters.py --include-suspect --tsv .scratch/merged-chapters-report.tsv
python detect_merged_chapters.py --books-dir ~/data/weixin/books
python detect_merged_chapters.py --include-output   # 连 output/<id>/chapters 中间产物一起体检
python detect_merged_chapters.py --catalog-root output   # 默认值：用导出时的 _catalog.json 核对缺章
python detect_merged_chapters.py --refresh-cache    # 忽略干净书缓存，全量重扫
```

直接跑脚本即可：没问题且 JSON（及对应 `_catalog.json`）没变的书走 `.scratch/merged-chapters-cache.json`，下次跳过；命中档每次重扫。`--refresh-cache` 全量重扫并写回缓存，`--no-cache` 不读写缓存。判定参数或脚本变化会使缓存失效。

脚本不删除、不移动、不修改任何电子书文件；除可选 TSV 外，只额外写上述缓存。

## 判定规则（脚本已实现）

只看各章正文字数分布（去空白后按字符数），另用「最大章里是否混入其他章名 / 其他章正文」
做交叉印证：

| 情况 | 处理 |
|------|------|
| ≤2 章 | **豁免**：诗词画册、单篇，单章一两万至两三万字属正常 |
| 3—4 章 | **默认不判定**：「版权信息 + 正文 + 附录」天然单章占比高；可用 `--min-chapters 3` 放宽（会误报） |
| 5—9 章 | 单章 ≥70% 且其余多为小章 → 报；≥90% → 严重（上下卷各半属正常，不报） |
| ≥10 章 | 单章 ≥50% 且其余多为小章 → 中度；≥80% → 严重；仅过半但其余章不小 → 可疑 |
| 任意章数 | 最大章占比 ≥30%，且其中确实混入 ≥2 章其他章正文（该章 ≥50% 抽样窗口命中）或 ≥10 个其他章名 → 中度（强证据） |
| 任意章数 | 空章 + 标题占位章占比 ≥50% → 「多章无正文」（≥5 章才判定） |
| 任意章数 | 目录（`output/<id>/_catalog.json`）里有、导出章节里没有（容忍「第1章 序言」这类短前后缀差异），标题（≥4 字）以**非引用**形式**独立成行**出现在**非目录/索引类**章节正文中，且缺失数不超过已导出章数的 30% → 「章节缺失」（只认「短篇目被并进邻章」） |

「小章」= 正文字数 < max(200 字, 全书 1%)；「标题占位章」= 正文只有章名本身。
全书不足 5000 字（样本太小）不判定。

「章节缺失」的豁免项（这些不算缺章，别把它们当故障处理）：

| 情况 | 例子 | 为什么豁免 |
|------|------|-----------|
| 标题在正文里被空白/换行断开 | 「清明与孙都督伯泉出郊游迎恩隆禧二寺观郑尚 / 书园池」 | 阅读器里长标题折行导致章界错位；题目与正文都还在前一章里 |
| 标题只夹在句子中间 | 「中国王维研究会会长吴相洲教授指出…」 | 是机构名/引用/提及，不是篇目被吞 |
| 卷标题 | 「卷一 乐府」「卷五 五言律诗」 | 结构性标题，正文里常挂在相邻章首尾，本就不单独成章 |
| 作者分组行 | 「柳永 八首」「李齐贤 五十三首」 | 分组抬头（目录用空白分隔姓名与首数），本来就没有自己的正文 |
| 出现位置在目录/索引类章节 | 章名含「目录 / 总目 / 索引 / 篇目 / 书目」的章 | 这类章逐行罗列篇名，不能当证据 |

形态判定入口是 `title_body_form()`：独立整行 = `line`（报）、折行 = `wrapped`（豁免）、
句中 = `inline`（豁免）。「章节缺失」只在 `line` 时成立。

## 分档含义

| 分档 | 含义 | 建议 |
|------|------|------|
| 严重 | 单章 ≥80%（或 5—9 章时 ≥90%）且其余章基本是占位章 | 基本可确定是合并，直接重抓 |
| 中度 | 单章过半且其余多为小章，或有强交叉证据 | 抽看一两章正文后重抓 |
| 可疑 | 单章过半，但其余章都有实质正文（默认不列出，加 `--include-suspect`） | 可能只是正常长章 |
| 章节缺失 | 目录里的章在导出结果中缺失，其标题独立成行地出现在别章正文里（常见：少量词牌/篇目被并进邻章） | 该类命中较多，量大的书优先重抓 |
| 多章无正文 | 大量空章/标题占位章 | 属于另一类缺失，单独复核 |

输出里的 `最大章为书前/书末项` 是关键提示：占到全书大头的章若是「后记 / 附录 / 索引 /
参考资料 / 版权信息 / 目录」一类，几乎可以确定是合并；若是「卷四」「第七章」这类正文性章名，
再结合 `混入其他章名`、`其他章正文重复` 两列判断。

## 输出

```
[严重] 6ee32660813ab69aeg01341d 唐代文学研究年鉴（2016） 章 67 字 319947 \
```

`--tsv <path>` 写出明细表（级别 / book_id / 书名 / 章数 / 总字数 / 最大章序号 / 最大章名 /
占比 / 其余小章数 / 小章占比 / 空章数 / 占位章数 / 最大章为书末项 / 混入章名 / 正文重复章 /
目录缺失章 / 来源）。
`--json` 输出机器可读结果。

## 发现后如何处置（需用户确认后再动）

1. 把命中的 `book_id` 追加到 `data/new_books.txt`（格式 `ID,书名,作者`），可置顶优先抓。
2. 删掉已抓取的产物。**两个位置都要清掉**，缺一个都会让「不加 `--force` 的重跑」直接复用旧结果：
   - `~/data/weixin/books/<id>_书名.json`（成品）——留着会被「已存在 JSON」跳过。
   - `output/<id>/`（中间产物）——留着会被续传逻辑当成「已到目录末章」：
     `export_precise.py` 读 `output/<id>/chapters` 里最后一个 md 的标题，只要它等于目录末项，
     就打印「全书导出完成」，**不打开阅读器**，直接用这些旧 md 拼出成品 JSON；
     `--force` 只跳过「已存在 JSON」检查，绕不过这个判定。
     实测：只删成品、留着 `output/<id>/` 重跑，新成品与旧成品逐字节相同。
   删除属于破坏性操作：先确认清单，优先 `mv` 到 `~/.Trash/<批次>/` 而不是直接 `rm`；
   中间产物也建议 `mv`（例如 `~/.Trash/<批次>/output/<id>/`）而不是 `rm -rf`，必要时还能对照。
3. 用修好的逻辑重抓：`python export_precise.py --prefer-largest-screen`（`--force` 可跳过「已有 JSON」检查）。
   **默认用大屏**：大屏单屏字数多、翻页次数少，既快又不容易把相邻章的正文并进同一屏；
   只有在明确要用笔记本内建屏时才传 `--no-prefer-largest-screen`。
   若 `output/<id>/` 没清干净，脚本会由 `assert_resume_artifacts_trustworthy()` 直接报错中止，不再静默复用。
4. 重抓后再跑一次 `python dedupe_shelf_books.py`，让清单与本地成品保持一致。

## 边界

- 只体检 `~/data/weixin/books/*.json`（可用 `--books-dir` / `BOOKS_DIR` 覆盖）；`--include-output` 才会看中间产物。
- 默认缓存干净书；要核对缓存是否误跳，用 `--refresh-cache`。
- 判定是启发式：短书豁免、5—9 章收紧门槛，但「单章占比高」本身不等于故障，务必人工复核 `可疑` 档。
- 交叉证据（章名混入 / 正文重复）是抽样比对：24 字窗口、命中率 ≥50% 才算「该章正文被合并」，避免套话/引文造成的偶然撞句。
- 「章节缺失」是保守规则：只在标题**独立成行**时成立，宁可漏报折行/句中/结构性标题，也不把它们当故障。
  作者分组行只认「姓名 + 空白 + 首数」；无空白的「X四首」（词牌组篇目，如「浣溪沙四首」）分不出来，仍按信号保留。
- 规则要改就改 `detect_merged_chapters.py` 与本 skill（`.agents/` 与 `.claude/` 两份保持一致）。
